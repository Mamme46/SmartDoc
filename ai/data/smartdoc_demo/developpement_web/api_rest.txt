Une API REST permet à plusieurs applications de communiquer au moyen du protocole HTTP. Chaque ressource est identifiée par une URL, souvent appelée endpoint, et les opérations courantes s'appuient sur des méthodes standard. GET sert à consulter des données, POST à créer une ressource, PUT ou PATCH à la modifier, et DELETE à la supprimer. Le serveur renvoie généralement un document JSON accompagné d'un code de statut : 200 indique une réussite, 201 une création, tandis que 400, 401 ou 404 signalent respectivement une requête incorrecte, un accès non autorisé ou une ressource absente.

Une conception solide prévoit une structure de réponses cohérente, la pagination des longues listes et une validation stricte des paramètres. L'authentification peut utiliser une clé d'API ou un jeton Bearer transmis dans l'en-tête Authorization. Les échanges doivent être chiffrés avec HTTPS et les permissions vérifiées côté serveur. La documentation précise les routes, les champs attendus et les erreurs possibles. Des tests vérifient notamment l'idempotence des requêtes et le comportement en cas de réseau instable.
